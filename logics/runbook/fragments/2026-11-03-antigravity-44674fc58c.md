# Antigravity worker isolation — mission 44674fc58c

## Scope and conservative choices

Implement worker-owned login for remote Antigravity, with mandatory bubblewrap,
a fresh memory-backed HOME, no controller credential transfer and no token copies.
The installed CLI is mounted read-only. The only authentication mount is the
owner-only regular worker token file. A nonblocking exclusive flock stays held
on that file throughout execution and cleanup. Concurrent cdx attempts fail busy;
external native agy processes do not participate and must use separate scheduling.
The token is read-only until a real measurement establishes in-place refresh.
Do not widen this to a profile-directory mount or a keyring mount.

This change rests on a host measurement and spans launch, worker and sandbox
layers (ADR 030). This mission fragment records that evidence and its outstanding
acceptance conditions, as requested, without appending history to shared runbooks.

## Egress policy and pending measurement

Candidate HTTPS destinations, resolved on the trusted worker per attempt:

- `oauth2.googleapis.com` (OAuth refresh candidate)
- `cloudcode-pa.googleapis.com` (production inference candidate)
- `daily-cloudcode-pa.googleapis.com` (Antigravity inference candidate)

Only their public resolved addresses on TCP 443 and DNS to 1.1.1.1/9.9.9.9
(TCP/UDP 53) are allowed. DNS resolving a candidate to a non-public address fails
closed. Existing IPv4 private/link-local/loopback/CGNAT and IPv6 private/link-local
rejects remain before destination accepts. `--network-access` never widens this
provider policy. Address-based HTTPS filtering does not distinguish virtual hosts
sharing a Google address. Public tool browsing is intentionally unavailable.

On Host B, as the ordinary worker service user `user`, run this read-only agent
task from the source checkout (requires strace and the existing worker login):

```bash
uv run --no-sync python -m scripts.probe_antigravity_worker
uv run --no-sync python -m scripts.probe_antigravity_worker --isolated
```

The probe asks only for OK and forbids tools, file access and commands. It does
not change services or repository content. Native agy may update its own session
metadata. It prints only exit/status, normalized numeric usage, connect addresses,
candidate DNS answers and token inode/metadata/mode comparisons. Raw stdout,
stderr and connect trace remain on the worker and are removed with volatile
storage; token content is never printed or returned. It holds the same cdx lock.
Do not pass a token, SSH secret or raw auth trace to the mission sandbox.

Acceptance requires a real SUCCESS with usage, matching observed HTTPS peers to
the minimum Google destinations, and an explicit receipt for whether an actual
refresh changes token metadata while preserving its inode and 0600 mode. An
unchanged token after an ordinary request does not prove refresh behavior. Keep
the mount read-only until refresh has actually been observed. The second probe runs the same prompt through the shipped sandbox builder,
with a read-only empty checkout and volatile HOME, to establish isolated
acceptance with working bubblewrap namespaces. A token
absent/unsafe, expired session, refused action or non-SUCCESS result must alert
instead of initiating login. No live acceptance or refresh is claimed here.
