# Remote Claude headless execution — mission a6e124c639

The controller owns a dedicated long-lived Claude setup token in the profile's
`.cdx-remote-claude-token` file (0600). The operator obtains it with
`claude setup-token`, then supplies only its value to
`cdx auth claude-token <profile>` on stdin. No real token was generated or stored
for this mission. Existing local login data is deliberately not a fallback.

Remote Claude always uses bubblewrap, regardless of the caller's isolation flag.
The existing SSH bootstrap ships source and an attempt payload on stdin. A second
private stdin pipe passes the token through pasta/bubblewrap into a Python exec
shim, which exports it only when replacing itself with Claude. The worker never
writes a token file. Output forwarding redacts it before capture or transport.
Subprocess environment scrubbing and non-essential-traffic suppression stay on;
the sandbox environment allowlist excludes competing API/cloud/proxy credentials.
The worker mounts only its freshly allocated tmpfs attempt HOME, not a controller
or worker profile. HOME, configuration, Claude caches and traces are removed by
the common stop/finally lifecycle, with dead-home sweeping retained.

Conservative assumptions: the worker is Linux with matching Claude CLI, Python 3,
bubblewrap, pasta, nftables, namespaces and tmpfs `/dev/shm`. Without explicit
network access, allow only public DNS and HTTPS to inference addresses resolved
for `api.anthropic.com` at startup. DNS changes require a fresh attempt. Explicit
network access preserves the existing public tool-network policy. Do not use
`--bare`: it ignores OAuth. Bubblewrap supplies the tool permission boundary.
Fresh runs only; no remote continuation or worker login is introduced.

Implementation evidence lives in the remote transport/sandbox declarations and
fake-worker regression tests; no separate workflow chain is needed for this
bounded extension of the existing remote lifecycle. Tests assert token absence
from argv, wrapper environments, output/results and worker files, plus usage
parsing, missing-token guidance, storage permissions, network setup and cleanup.
Local checks are timed through `.mission-input/mission-test-runner.py`.

Initial validation exposed inherited GIT_DIR/GIT_COMMON_DIR/GIT_WORK_TREE and
RTK_DB_PATH variables interfering with unrelated fixture repositories and RTK
expectations. Final Python checks unset those variables only for the test process.
Development dependencies were installed with `uv sync --frozen --extra dev`;
the missing Rust toolchain was installed under `/tmp/cdx-mission-rust`.
No Git commit, push, PR publication or operator-host action was performed.

Real authenticated inference is intentionally untested: the mission has no
operator token. The fake worker is not evidence of real namespace availability
or service authentication. An operator may validate that separately using their
own credentials and approved worker; no deployment-only host check is requested.
