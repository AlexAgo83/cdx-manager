# Remote Ollama text generation (mission 339706dff5)

The supplied checkout is cdx-manager. This mission adds an Ollama branch to
its SSH worker protocol; it does not change the remote-ops supervisor deployment
or shared runbooks/design rules.

## Conservative assumptions

- A Linux worker already runs unauthenticated Ollama at `127.0.0.1:11434`.
  The destination is fixed in supervisor code, not selected by the controller,
  prompt, environment, request headers or sandbox client.
- An explicit `--model` or profile model is required. `/api/show` must succeed
  before inference; advertised cloud-backed and non-completion models are refused.
  No model pull, authentication or CLI version matching is attempted for Ollama.
- Prompts are read on the launching host and sent as content over SSH stdin,
  then client stdin and HTTP. This is text generation only: the model receives
  no autonomous coding tools, and no repository edits are promised.
- For isolated runs the worker owns a mode-700 temporary relay directory and
  mode-600 Unix socket. The sandbox gets a read-only bind of that directory,
  a read-only checkout and its own disconnected network namespace. The relay
  permits only POST `/api/show` and non-streaming POST `/api/chat`, for the
  selected model and a single text user message; it does not proxy headers,
  redirects, arbitrary URLs, model management or any host/LAN destination.
  No `~/.ollama` or model files are mounted. `--network-access` does not expand
  this text client's network permissions. SSH EOF/signals terminate the client;
  completion, failure and cancellation remove the relay directory.
- Existing remote continuation/failover restrictions remain. Ollama results
  identify text generation and include the generated text, raw API prompt/output
  counts and normalized token usage. Existing unknown-cost/budget rules apply.

## Verification

Every local check is timed through `.jarvis-input/mission-test-runner.py`;
receipts are preserved in `.jarvis-artifacts/mission-tests.jsonl`.

The initial baseline `npm test` had six Git/RTK environment-related failures:
Spire supplies `GIT_DIR`, `GIT_COMMON_DIR`, `GIT_WORK_TREE` and `RTK_DB_PATH` for
its own sandbox. Removing these variables for the disposable-repository test
process restores the intended test environment, without changing repository Git
permissions. The initial lint lacked ruff; `uv sync --frozen --extra dev`
installed locked development dependencies. Cargo was absent; a public minimal
Rust toolchain was installed temporarily for the tray tests. Vendor toolchain
Python files briefly appeared in lint's search scope; moving that temporary
toolchain out of the checkout restored clean lint without exclusions.

Fake API/SSH tests exercise successful ordinary and isolated worker generation,
controller-side prompt content, no authentication, usage and registry output,
missing models, cloud/non-completion model refusal, unreachable APIs, rejected
management/alternate-destination calls, relay cleanup and sandbox construction.
The isolation integration uses a synthetic confinement wrapper; actual namespace
startup remains covered by the repository's optional real sandbox tests.

No production worker, operator secrets, Git commit/push or PR creation is used.
The human review should check the fixed loopback/local-model assumption and the
relay allowlist. A real Ollama model and worker namespace environment were not
available for an end-to-end host measurement; fixtures do not certify a deployed
host. This is a code delivery, with no host recovery or deployment claim.

Final validation is green:

- `npm run lint` (including documentation checks, Ruff and Python compilation).
- `npm test`: 1,440 passed, four optional real-sandbox tests skipped. The test
  process uses the prepared virtualenv on PATH and unsets the four inherited
  Git/RTK variables described above.
- `cargo test --manifest-path tray/Cargo.toml`: 99 passed, using the temporary
  public Rust toolchain outside the checkout.
- `npm pack --dry-run` and `uv build --wheel --out-dir .jarvis-artifacts/dist`.
- `logics-manager lint --require-status`, `logics-manager audit --group-by-doc`

The focused remote transport/worker suite passed (63 tests); the final focused
